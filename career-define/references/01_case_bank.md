# 사례 은행

## 연표 (맨 위)
| 기간 | 회사 | 직함 | 팀 규모 | 주요 역할 한 줄 |
|---|---|---|---|---|

## 사례 카드 형식
```
## [사례명 — 주도한 일, 예: "정체된 B2B 상품 재설계"]
- 기간 · 역할 · 팀 규모:
- 문제: 왜 이 일이 필요했나 (시작 시점의 숫자가 있으면)
- 내가 한 것: 직접 한 것 / 리드한 것 / 다른 팀이 한 것
- 결과: 숫자 + 기준(기간, 비교 대상) + 출처 유형(공식 / 대시보드 / 기억)
- 실패·한계: 이 일 안에서 안 된 것, 다시 하면 바꿀 것
- 능력 태그: 0→1, 턴어라운드, 데이터 분석, 파트너십, 조직 운영 … (지원자에게 확인)
- 실무 수준 (지원자 자기 평가): 면접에서 세부 질문을 받으면 어디까지 답할 수 있다고 보나
```
- 실패가 같은 일 안의 한계면 '실패·한계' 칸에, 다른 일(따로 시작해 접은 프로젝트 등)이면 별도 카드로 만든다.
- 답이 없는 칸은 '미확인'.

## 질문 은행
**배경**
- "이 일은 언제부터 언제까지, 어떤 역할로, 몇 명과 했나요?"
- "왜 이 일이 필요했나요? 시작할 때 무엇이 문제였나요?"

**숫자**
- "그 숫자는 언제부터 언제까지, 무엇과 비교한 건가요?"
- "그 숫자는 어디서 본 건가요? 공식 보고, 대시보드, 기억 중 어느 쪽인가요?"
- "시작할 때 숫자는 얼마였나요?"

**기여**
- "본인이 직접 한 것과 팀이 한 것을 나누면요?"
- "본인이 없었다면 무엇이 달랐을까요?"

**실무 수준**
- "그 도구는 직접 썼나요? 어느 수준까지요? (예: 쿼리라면 조인·집계·윈도우 함수까지)"
- "면접관이 이 일을 깊게 물으면 어디까지 답할 수 있을 것 같아요?"

**실패**
- "이 일에서 가장 안 된 것은 무엇인가요?"
- "같은 시기에 시작했다가 접은 일이 있나요?"

**빠진 사례 찾기** (1단계에서 한 번, 막히면 다른 질문으로)
- "이력서에는 안 썼지만 시간을 많이 쓴 일이 있나요?"
- "가장 오래 붙잡고 있던 문제는 무엇이었나요?"
- "실패해서 이력서에서 뺀 일이 있나요?"

## 복기에서 갱신하기 (갱신 모드 0-1단계)
`debrief_log.md`는 질문을 고르는 재료다. 카드에 옮길 답의 출처가 아니다.

1. **반복 분류 찾기** — 여러 면접 누적 표와 각 면접의 '다음엔' 칸에서 2건 이상 나온 분류·주제를 고른다. 1건은 메모로만 본다. `[career-define 갱신 요청]` 블록이 있으면 그것을 먼저 따른다.
2. **관련 카드 연결** — 반복된 질문이 가리키는 사례 카드를 찾는다. 대부분 '내가 한 것'·'실무 수준'·'실패·한계' 칸이 비어 있거나 '미확인'이다.
3. **그 카드부터 질문** — 기존 질문 은행에서 해당 칸 질문을 쓴다. 예: 면접에서 "수요 예측은 본인이 했나요?"가 반복됐으면 기여·실무 수준 질문("본인이 직접 한 것과 팀이 한 것을 나누면요?")으로 묻는다.
4. **지원자 답으로만 채우기** — 복기의 '내 답 요약'을 그대로 옮기지 않는다. 지원자가 이번에 확인한 내용만 적는다. 원칙 7(같은 칸 두 번까지)을 그대로 따른다.
5. **관련 카드가 없을 때** — 반복 질문이 기존 사례로 설명되지 않으면 '빠진 사례 찾기' 질문으로 새 카드를 찾는다.
6. **근거 남기기** — 고친 칸마다 `transcript.md`에 "복기 근거: [회사·단계·질문 번호]"를 적는다.
